Russian Explorer

Version 8 derives from explorer/7/sample1.html. All 24 standalone UTF-8 HTML samples preserve the source interface, navigation, virtual files, menus, storage transactions and maximum depth. Version 7 is unchanged. The interface is English; folder names are Russian letters.

Alphabet and structure

The exact folder order is:

А Б В Г Д Е Ё Ж З И Й К Л М Н О П Р С Т У Ф Х Ц Ч Ш Щ Ъ Ы Ь Э Ю Я

The root is depth 0. Every folder at depths 0–65535 offers exactly 33 child folders. Depth 65536 is the original terminal level with no child folders; files can still be created there. The tree is generated on demand, without allocating every possible branch. The drive is called Russian drive.

Navigation

Click a letter or type its Russian keyboard character to enter a folder. Uppercase and lowercase input are accepted and paths use uppercase letters. Enter a slash-separated path such as /А/Ё/Й/Ъ/Ы/Ь in the address bar. Leading and trailing slashes are optional; empty input opens the root. Unicode NFC normalization accepts decomposed Ё and Й. Latin lookalikes, digits, multi-letter segments and empty interior segments are rejected.

Back and Forward use session history. Up and Backspace move one level up; Home and the drive button open the root. Alt+Left, Alt+Right and Alt+Up provide navigation shortcuts. Breadcrumbs open earlier folders; long paths show the last 24 components and an ellipsis with a level-jump dialog. Copy path copies the complete Cyrillic path, with a selection fallback when clipboard access is unavailable. Grid and list views are retained.

Virtual files

New file creates a name-only virtual file at the current path. These files contain no executable program or file content and are not downloaded to the operating system. Names are trimmed, NFC-normalized and limited to 1–255 Unicode code points. Slashes, backslashes, control characters, dot and dot-dot are forbidden. Case-insensitive duplicate file names and names matching available child folders are rejected. Е and Ё, И and Й, Ъ and Ь remain distinct.

Saving and isolation

IndexedDB saves the current path, view mode and file records transactionally. Reloading restores the last saved position and files; navigation history starts fresh. Each sample uses its own 16-digit hexadecimal storage key as its IndexedDB database name and legacy localStorage migration key. The files store has folder and unique case-folded-name indexes. The settings store holds state and migration status. An old localStorage save, if present under that sample key, is removed only after a successful migration transaction.

Use the same browser profile and origin to retain saves. Browser storage clearing, private-session termination or browser eviction can remove data. Saves are local to this device, not synchronized. Storage failures keep the interface blocked with a reload message; operation failures report an error. Prefer serving over HTTP(S), as file-URL storage behavior depends on the browser.

Menu

New game clears this sample’s virtual files and returns to the root. Delete files removes selected files only in the current folder. Both retain the original password 1111, which is a confirmation mechanism rather than security. Share website shares the current sample URL without query or fragment and never includes saved data. About displays the program name and Program ID. Menu keyboard navigation, dialogs, responsive layout and accessibility labels are preserved.
