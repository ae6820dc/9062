Chinese Explorer

A standalone adaptation of explorer/7/sample1.html. Each sample contains all its HTML, CSS and JavaScript and requires no network dependencies. The English interface explores an implicit Chinese drive, creates virtual files, and automatically saves progress in the current browser.

Samples and isolation

Open any of sample1.html through sample22.html. All 22 files are identical except for their Program ID and storage key. Each identifier contains exactly 16 hexadecimal characters; all 44 identifiers are distinct. The storage key names the sample's IndexedDB database and legacy localStorage entry. No sample shares a database with another sample or the source Explorer.

Unicode alphabet and stable folder identity

The alphabet is exactly the inclusive CJK Unified Ideographs base block U+4E00–U+9FFF. Its size is 0x9FFF − 0x4E00 + 1 = 20,992. Folder index i (0–20,991) maps to code point 0x4E00 + i; displayed ordinal is i + 1. The first folder is 一 (U+4E00, ordinal 1), the last 鿿 (U+9FFF, ordinal 20,992), and 中 is U+4E2D, ordinal 46. This order never depends on language, collation, font or browsing history. Each original code point identifies a separate folder. There is no pinyin, simplified/traditional conversion, Unicode normalization or merging. A missing glyph in a device font does not remove its folder.

Navigation and the depth limit

Click a folder or type its CJK character outside an input to enter it. Back/Forward retain navigation history; Up and Backspace go to the parent; Home and Chinese drive return to the root. Alt+Left, Alt+Right and Alt+Up retain their source shortcuts. Enter an absolute character path such as /一/中/鿿 in the address bar. Copy path copies its full lossless value with a manual selection fallback. Root has depth 0. Up to 65,536 characters are accepted; longer or invalid paths are rejected.

The depth counter and progress bar always show the current position. Breadcrumbs show the last 24 folders. For longer paths the ellipsis opens the original “Jump to level” dialog, which can navigate to any earlier level from 0 to the current depth. Navigation is iterative; no recursive directory DOM is built. IndexedDB stores path indices as a Uint16Array (at most 131,072 bytes of index data). The active path uses an index array; history retains typed changed suffixes rather than a full copy per step. Traversal of a path of depth d performs O(d) path work rather than enumerating branches.

Every folder at depths 0 through 65,535 offers precisely 20,992 child folders. Depth 65,536 is the terminal boundary and has no children, as in the source's maximum-depth behavior. Virtual files can still be created there.

Search and direct jump

The Find / jump field accepts one CJK character, a code point such as U+4E2D (case insensitive), or a decimal ordinal 1–20,992. It scrolls to and focuses the corresponding folder without opening it or enumerating all folders. Click the focused folder to enter it. “List start” jumps to ordinal 1. Invalid values produce a message without changing the path. The same controls work in grid and list views.

Virtual rendering and mobile behavior

A fixed-height scrolling viewport uses a single spacer for the logical list height. The renderer calculates the visible row interval and two extra buffer rows on each side, then creates buttons only for that interval. It computes each folder name directly from its index. There is no array of 20,992 folder objects and no per-level folder collection. Scrolling is coalesced with requestAnimationFrame; ResizeObserver recalculates columns after resize. DOM size depends on viewport dimensions, not directory size. User-created files follow the folder sequence and are also virtualized. List view uses one column. Mobile view hides the sidebar, wraps controls and uses a touch-scrollable viewport with larger folder targets. At maximum depth only user-created files are listed.

Automatic storage and virtual files

Successful navigation and view changes commit the exact index path and view mode to IndexedDB. Files are stored only when created, with their folder's character path, name and creation time. No implicit folder objects are saved. Reload restores the exact path, files and view mode; back/forward history starts afresh as in the source. Failed transactions do not update the visible location. Storage errors and blocked databases are reported. Storage depends on browser availability and quota; clearing browser data removes local saves.

“New file” creates a name-only virtual file, not an executable or editable content file. Names allow 1–255 characters, excluding path separators, controls, “.” and “..”. Case-insensitive duplicate names and existing folder names are rejected. The menu retains Share website, About, Delete files and New game. The original password 1111 protects deletion and reset; it is a user interface guard, not encryption. Delete files affects selected files in the current folder. New game clears this sample's files and returns to root.

UTF-8 exports and restoration

The source has automatic saving and website sharing but no download export. This version adds “Export save (JSON)”, “Import save (JSON)” and “Export standalone HTML”. JSON format ChineseExplorer1 includes the path as original CJK characters, view preference and all created file records. Blob downloads explicitly use UTF-8. Imports validate paths and file names before replacing this sample's save in one transaction; a failed transaction rolls back. Import is a replacement operation, so export the existing save first if needed.

The standalone HTML embeds both the complete application and its current save. It works offline without fetching assets. On its first opening it restores the embedded save into a separate database whose name includes -export- and a fresh export identifier; later openings preserve progress made in that exported copy. Each new HTML export receives its own database identity; reopening the same exported file retains that copy’s later progress. Browser restrictions may prevent IndexedDB for file URLs; in that case open the HTML through a local HTTP server. Website sharing sends only the URL, not your saved files. Exported HTML and JSON contain all saved file names and paths, so share them only when intended.

Mathematical capacity

With b = 20,992 and D = 65,536, exactly bd distinct folders exist mathematically at depth d. There are bD terminal paths (approximately 10283,250). Including the root, total logical directory count is (bD+1 − 1)/(b − 1). This is an implicit mathematical tree, not allocated disk storage. Device memory and IndexedDB capacity limit actual user-created files and saved browsing history, not the number of possible branches.
