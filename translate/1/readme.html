A static HTML/CSS/JavaScript multilingual dictionary for Hungarian, English, German, French, Spanish, Italian, Russian, Japanese and Latin. All 72 directed pairs use the same lookup engine. It supports exact lookup, alternatives grouped by sense, available grammatical information, prefix suggestions, history, favorites, clipboard copying, JSON export and downloadable offline dictionaries. There is no external translation API, telemetry, CDN, remote font or runtime dependency.

Installation & use

The final published location is https://ae6820dc.github.io/9062/translate/1/. All three programs, data and supporting files are under 9062/translate/1/.

Serve this directory over HTTPS or localhost; keep its paths intact. No build, API key or package installation is required to run it. For local development, from the repository root:

python3 -m http.server 8000
# Open http://localhost:8000/translate/1/index.html

Choose a sample, choose distinct source and target languages, then search a dictionary base form or phrase. Accents are significant. Matching uses NFC Unicode normalization, Unicode default lowercase, then NFC again; it does not strip accents, transliterate, stem or infer translations. Suggestions use the same normalized prefix. Japanese forms, Cyrillic and Latin diacritics are retained exactly apart from canonical normalization and surrounding whitespace. Source spelling and historical orthographic quirks are not silently corrected.

Swap reverses the language direction; it keeps your query so you can edit or replace it. “Save” stores a favorite lookup, and “Recent” stores at most 50 searches. Favorites are capped at 500. Both stay on this device, separately for each sample. Exports contain the complete Program ID, Unix millisecond timestamp, dataset version, displayed lexical records, source/license metadata, favorites and history. Export filenames contain the Program ID and timestamp. Exported lexical data retains its original licensing obligations. Clipboard access depends on browser permissions.

Definitions of counts: A headword is a distinct normalized form explicitly supplied as a lemma (WordNet) or source headword (FreeDict). Inflected forms, phrases, spelling variants and names genuinely present in a source remain separate when their normalized forms differ. Headword–sense associations count a headword once for each distinct source sense. Lookup forms include complete FreeDict target phrases indexed for reverse lookup; these are not added to the headword target merely because they can be searched. Pair coverage counts unique source lookup forms with at least one target form on the same attested sense. It does not count translation combinations, and its value may differ by direction. The full manifest also reports source headwords with a translation and aligned senses for every pair.

Sources, attribution & legal reuse

Data is drawn from two pinned, open upstream repositories. The linked original files, byte-level SHA-256 hashes, precise revisions, license identifiers, attribution notices and compressed original source snapshots are recorded in data/manifest.json. Original source files are distributed under data/sources/; they are not downloaded into the application database. Reuse must follow the corresponding source licenses. The original application and tools use the MIT license, which does not relicense the lexical data.

Coverage & linguistic limitations

Hungarian, English and Japanese exceed the 100,000-headword target in this release. German, French, Spanish, Italian, Russian and Latin remain below target. Each direction has real, nonzero coverage, but any given source sense may lack a target. The app shows an honest “no attested translation” response instead of filling gaps. Proper names, phrases, multiple spellings and inflected forms occur in the real datasets; counts are not restricted to single-word dictionary lemmas. FreeDict translation quotes can be explanatory phrases; reverse lookup requires the complete quoted phrase, not an arbitrary word inside it. Historical Hungarian FreeDict spelling sometimes uses õ/û where modern spelling uses ő/ű; accents are preserved rather than guessed. Latin macrons are only available when supplied in a source; the app does not manufacture macronized forms.

Wiktionary/WOLF mappings and source sense alignment can contain errors; WordNet synonyms need context. Some source records have only part of speech, not a definition or detailed morphology. No external sense mapping or bilingual-gloss pivot is used. Neither complete inflection tables, arbitrary sentence translation nor 100,000 words in every pair is promised. A current JMdict or newer larger wordnet can be integrated later after explicit license and alignment checks. Empty or visibly corrupted forms are rejected and rejection counts are recorded per source in the manifest.

Offline behavior & storage

Open online once and wait for “Application shell ready offline.” Then choose a source language and press “Download.” Its lexical index and all sense partitions needed for translation to the other eight languages are saved in IndexedDB. Completed chunks are retained on pause, interruption, tab close, network failure or quota failure; repeating the download resumes without redownloading committed chunks. Download progress describes chunks and compressed transfer sizes, not the larger indexed storage footprint. Shared partitions are reused across downloads and all three samples. A lookup also caches only its required partitions, so previously searched terms can work offline without a full-language download. To guarantee all available terms for a source, finish its full download. Downloading a source does not guarantee reverse offline lookup until the reverse source's lexical data is present.

Browser quota, private mode and storage eviction can remove data. Persistent storage is requested when downloading; the browser may decline it. The app reports download/storage failures instead of marking missing data as complete. Use the browser's site-data controls to remove downloaded dictionaries. This also removes saved settings; all samples on this origin share the dictionary store. A reload while offline works only after the service worker has installed the application shell. file:// is not supported; use HTTPS or localhost.

Technical architecture

All three HTML samples load the same local CSS and JavaScript. A dedicated Web Worker fetches the versioned manifest, normalizes queries, locates sorted range shards using binary search, decompresses gzip with DecompressionStream, checks compressed size and SHA-256, validates uncompressed size and count, and commits at most 1,024 records per atomic IndexedDB transaction. The completion marker commits with the data, never before it. The worker does not load the full lexicon or sense database into memory. IndexedDB stores lexical keys and senses with a compound language/normalized-form index for exact and prefix lookup. Suggestions are debounced, limited to eight, and lookup results paginate in batches of twelve matching senses. A compact per-sense target-language bitmask skips partitions that cannot supply the requested language; no guessed links are added. There is no cross-product translation database in RAM.

The service worker is scoped to /translate/1/. It caches the three samples, launcher, shared app files, manifest and original license notices. Large dictionary partitions are not duplicated in CacheStorage. Lookup fetches only missing compressed partitions; in-flight duplicate requests within a worker are shared. Imports are limited to two concurrent shards, and superseded lookups stop before loading further sense partitions. Source snapshots are for developers and legal source distribution, not runtime loads. Dataset versioning changes the shared IndexedDB name. A production update must update the manifest version and shell cache version together; retained old databases may be removed through browser site settings. No unrelated service worker caches are deleted.

Reproducible data build & incremental expansion

git clone https://github.com/omwn/omw-data.git /tmp/omw-data
 git -C /tmp/omw-data checkout 406bf83b3c507a3d1f26e88252d5d66893fd36bf
git clone https://github.com/freedict/fd-dictionaries.git /tmp/fd-dictionaries
 git -C /tmp/fd-dictionaries checkout 5bdceeac8d0dba3298c1bebe734f60d54dad30f7
python3 translate/1/tools/build_data.py --omw /tmp/omw-data --freedict /tmp/fd-dictionaries
python3 translate/1/tools/write_coverage.py
python3 translate/1/tests/validate_data.py

Build tools use Python's standard library, a disk-backed SQLite staging database and bounded output shards. Original source files can also be extracted from data/sources/, with their upstream relative paths and hashes taken from the manifest. The importer requires pinned, clean source checkouts to prevent unrecorded provenance changes. All generated shards and gzip source snapshots are deterministic for fixed inputs and tooling. To expand, add a licensed dataset adapter, retain its source snapshot and notices, preserve its true sense identifiers (or explicitly reviewed mappings), regenerate the manifest and coverage, increment the dataset and shell versions, then run validation. Never merge distinct senses merely because they share an English string. Existing files in this directory are not deleted by the importer except its explicitly generated data/lex, data/concepts and data/sources artifact directories when replacing a successful build.

Program identities

These permanent identifiers were independently generated with a cryptographic random generator. Program IDs and Storage Keys are distinct 16-character uppercase hexadecimal values. Settings keys have the format unicode-translate:<Storage Key>:v1; Program IDs identify the application and exports, not local settings. Dictionary data is deliberately shared independently of settings.

Future Android packaging

No APK has been built. Package this whole directory, all compressed dictionary partitions, license notices and the sample selection menu index.html as local app assets. Use AndroidX WebViewAssetLoader on its HTTPS app-assets origin, a current Android System WebView with IndexedDB, workers, Web Crypto and DecompressionStream, and keep DOM storage enabled. Route all local paths, including worker fetches and gzip assets, to that asset origin without an HTTP Content-Encoding header on raw .gz files. Select a sample through the launcher to preserve independent identities. The app does not depend on service-worker support for locally packaged shell access; packaged assets provide it. A wrapper should add an explicit download/export bridge and clipboard integration if WebView's defaults are insufficient, test quota/storage lifecycle, back navigation and offline asset requests, and retain the licenses/source-access provisions when distributing data. The packaging step is separate from this web implementation.

Validation

The data validator recomputes counts and all 72 pair coverages from the compressed records, validates provenance and Unicode round trips, checks lexical references and original source hashes, and checks every local HTML link. Browser tests exercise all 72 directions with real shared senses, suggestions, Unicode, sample isolation, history/favorites, export identity, clipboard action, responsive layout, resumable download and offline reload. Run:

python3 translate/1/tests/validate_data.py
# Install test tooling outside the repository (or use an existing Playwright).
npm install --prefix /tmp/unicode-translate-tests playwright@1.56.1
# Run against a local server whose document root is the repository:
PLAYWRIGHT_MODULE=/path/to/node_modules/playwright node translate/1/tests/browser.cjs

See VALIDATION.md for the recorded results and remaining limits. The Unicode Translate GitHub Pages verification workflow waits for the deployed files to match the committed SHA-256 hashes, opens all three published programs, and runs the complete browser suite against https://ae6820dc.github.io/9062/translate/1/. Its downloadable artifact contains the live results and desktop/mobile screenshots.
